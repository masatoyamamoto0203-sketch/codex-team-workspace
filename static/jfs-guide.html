食品工場 在庫・入庫ラベル管理／V3.0.2／更新：2026-10-05

JFS-B運用支援版の使い方

ケースとバラの管理に、受入検品・使用可否の判定・ロット追跡を加えました。この資料は本アプリの操作手順です。JFS規格本文の代わりや、適合証明書ではありません。

最初に知っておくこと
入庫・旧データは「未確認」から始まります。検品が合格になるまで使用・出荷できません。現物と規格書を確認し、責任者が定めた担当者が判定してください。既存の「合格」の事実は、このアプリへの移行だけでは作りません。

1．今のデータを残して更新する

  1. 現在動いているアプリの起動画面で「データ保存先」を確認します。そのフォルダーをFinderで開いてください。以前の写真の場所と同じとは限りません。
  2. 起動画面でControl＋Cを押して終了します。別のPCやスマホからの操作も止めます。
  3. 現在のアプリのdataフォルダー全体を別の場所にもコピーして保管します。中のwarehouse.sqlite3が台帳です。削除しないでください。
  4. 更新版のZIPを展開します。新しいfactory-stock-appフォルダーに、現在のdataフォルダーをコピーします。新規運用であればコピー不要です。
  5. Macでは「起動_Mac.command」、Windowsでは「起動_Windows.bat」を開きます。Python 3.9以上が必要です。起動時に旧形式のバックアップをdata内へ作り、データ構造を更新します。
  6. 画面上部がV3.0.2 JFS-B運用支援であること、商品数・在庫・場所・担当者が引き継がれたことを確認します。空なら入力を始めず、起動画面のデータ保存先とコピーした場所を確認してください。

Macが起動ファイルを開けない場合、警告だけでは安全性は判断できません。ファイルの入手元と内容を確認したうえで対応してください。旧版へ戻す場合はV3.0のデータを旧版で開かず、更新前のコピーと旧アプリをセットで使います。更新後の取引は戻したデータへ自動反映されません。

2．担当者・場所・単位・商品を登録する

「担当者設定」→「保管場所設定」→「単位設定」→「商品台帳」の順に登録します。商品台帳は担当者・標準保管場所・単位をプルダウンで選択します。単位は「袋」「個」「kg」など、実際にバラを数える単位にします。ケース管理する商品は標準入数も入力します。

担当者名の選択は本人認証ではありません。責任者が操作できる人を決め、共用PCの利用を管理してください。最低在庫数はバラ換算の数です。

3．30ケース入ってきたら

例：30ケース × 20袋 ＝ 600袋
  1. 「入庫・ラベル」を開き、仕入先・仕入先ロット・商品・担当者を入力します。納品書番号と備考、仕入れ金額は任意です。備考が空でも発行できます。
  2. 製造日・入庫日・賞味期限・保管場所を入力します。賞味期限は製造日の1年後を初期表示しますが、実際の商品規格が優先です。月／年カレンダーを使えます。
  3. 数量の単位を「ケース」、数量を「30」、今回の入数を「20」にします。入数が12袋なら今回だけ12へ変更できます。1回の入庫内で入数が混在する場合は入数ごとに登録を分けます。
  4. 実測した入庫温度を20℃〜−20℃・0.5℃刻みで選びます。範囲外や、必要な測定精度がより細かい場合は丸めず、別の管理記録に実測値を残して責任者へ連絡してください。本版ではその温度は入力できません。
  5. 保存すると30/30〜1/30のケース番号と、それぞれ異なるバーコードのラベルが30枚できます。状態は未確認です。各ケースに対応するラベルを貼ります。

金額を入力した場合は総額を各ケースへ円単位で配分し、合計を保ちます。ラベルへ金額は印刷しません。社内用EAN-13形式です。市販流通用の正式JANの取得・発行機能ではありません。ケース番号や日付は台帳へひも付いており、数字自体に全部を埋め込んでいません。

4．検品して、使用できる状態にする

  1. 「JFS検品・追跡」を開きます。仕入先ロットなどで検索して対象を選びます。同じ検品結果を適用できる対象だけをまとめて選択できます（最大200件）。
  2. 担当者と実際の検品日時を選びます。保存日時も別に残ります。PCの時計とタイムゾーンを正しく設定してください。
  3. 規格書番号・版、仕入先の承認記録番号、温度基準の下限・上限、温度計と校正／点検記録の番号を記入します。文書本体は既存の文書管理で保管します。この入力欄は文書の有効性を自動確認しません。
  4. 包装と表示・数量の確認結果を選び、判定理由を記入します。
  5. 「合格」は、必須記録・温度範囲・期限・確認項目がそろった場合だけ保存できます。保留・不適合なら現物も隔離して、理由と処置を記録します。
  6. 保留・不適合から合格へ戻すときは、原因・処置・検証結果を追記します。合格できるかは工場の承認手順に従って判断します。ラベルを貼っただけでは使用許可にはなりません。

温度の−20〜20℃は選択肢の範囲です。安全基準を一律に設定したものではありません。微生物検査等の必要な結果は、規格書・検品理由欄などへ参照番号を記入し、判定前に原本を確認してください。

5．ケースで使う・バラで使う

作業入力表示例
1ケースを全部使う該当ラベルを読んで「使用」→「ケース」→1そのケースの残数0
20袋のケースから5袋使う「使用」→「バラ」→50ケース＋15袋
未使用29ケース＋開封分15袋ケースごとの記録を集計29ケース＋15袋（合計595袋）
数え直したら12袋だった「棚卸し」→「ケース」0＋バラ1212袋へ調整し、差異があれば検品を未確認へ戻す

使用時は使用部署と製造ロット、出荷時は出荷先と出荷伝票番号を入力します。棚卸し・廃棄は保留中も記録できます。使用・出荷は合格かつ期限内が条件です。別々の開封ケースの端数を自動で1ケースにまとめません。数量上の1ケース表示は「未開封」の証明ではありません。

最低在庫は、期限内かつ検品合格の在庫合計で判定します。定数未満で警告、1バラ単位のとき点滅します。期限が残り3〜6か月は黄、3か月未満と期限切れは赤です。

6．スマホで読み取る

  1. 通常起動中ならControl＋Cで終了し、Macの「スマホから使う_Mac.command」を開きます。
  2. Macとスマホを同じ社内Wi-Fiにつなぎ、起動画面に出たhttp://…:8765/mobile.htmlをSafari等へ入力します。127.0.0.1はスマホ用ではありません。
  3. 「カメラで撮影」からバーコード全体を撮影するか、13桁を入力します。表示された商品・ケース番号・検品状態を確認します。
  4. 担当者・使用／出荷等・ケース／バラ・数量・追跡番号を入力し「在庫に反映する」を押します。保存成功と新しい残数を確認して完了です。

撮影だけでは在庫は変わりません。Macの起動とネットワーク接続が必要です。Wi-Fiの端末間通信制限やファイアウォールで接続できない場合は社内ネットワーク担当者へ確認してください。本版には外出先からの公開接続、アカウント認証、営業先用閲覧権限、オフライン同期はありません。

7．訂正・削除・追跡

商品・入庫・出庫等は各画面の「変更・修正」を使います。担当者と理由、変更前後の値を記録します。入庫の訂正後は再検品が必要です。入数の間違いは出庫前なら誤った入庫を取り消して正しい入数で再登録し、古いラベルを破棄します。出庫済みなら責任者が関連記録を確認してください。

削除は通常の一覧から除外する方式です。取消・削除履歴は残ります。後続操作のある出庫履歴は取り消せません。数量修正は棚卸しで行います。出庫取消で戻った在庫も再検品します。検品記録は消さず、訂正理由を添えて新しい判定を追加します。

「JFS検品・追跡」で仕入先ロット、管理コード、製造ロット、出荷先、伝票番号を検索できます。訂正前の情報や取消済み取引も検索対象です。検索結果CSVと全記録JSONを保存できます。製造の配合・歩留まり・製品ロットへの自動変換は未実装なので、製造記録と製品入庫ロットの対応表を併用してください。

8．データを保存する（バックアップ）

画面上部の「データを保存」を押します。
  1. 入力途中なら、先にその画面の「保存」「在庫に反映する」などを押して登録を完了します。
  2. 画面上部の「データを保存」を押します。スマホ用の画面にも同じボタンがあります。
  3. warehouse-日付-時刻.sqlite3というファイルのダウンロードが始まります。Macではブラウザのダウンロード一覧またはFinderの「ダウンロード」を確認してください。保存場所はブラウザの設定によって変わります。
  4. 保存したファイルは開いて入力するものではありません。復元用として保管します。復元時だけ、ファイル名をwarehouse.sqlite3にして下記手順で使います。

このボタンは登録済みデータのコピーを保存します。入力途中の内容の登録や、アプリ本体のダウンロードは行いません。ダウンロード完了はブラウザの一覧で確認してください。

「復元用データを保存（SQLite）」は、起動中でも整合性のある台帳コピーを作ります。終業時や重要な更新前に保存し、日付入りの名前で別の機器にも保管してください。保存期間・責任者・点検頻度は工場で承認して定めます。自動削除はしません。

復元時は全端末の操作を止めてアプリを終了し、現在のdataを退避します。選んだバックアップを、新版のdata/warehouse.sqlite3へコピーして起動し、最終取引と数量を確認します。バックアップ以後の記録は含まれません。JSON／CSVを読み戻す復元機能はありません。定期的に別フォルダーで復元試験を行ってください。

9．JFS-Bとの関係と、工場で必要な準備

参照：JFSM公表のJFS-B Ver.3.0（2026-10-03確認）。下表は当アプリの支援範囲を整理したもので、規格本文の転載や完全適合の宣言ではありません。

参照分野このアプリの支援別途管理するもの
FSM9訂正・取消履歴、記録出力文書承認・保存方針、アクセス管理
FSM13.1・13.2仕入先と承認記録の参照仕入先評価・承認台帳と再評価
FSM14入庫と使用・出荷の検索製造工程でのロット対応、追跡試験
FSM17・19温度、計器記録参照、検品校正、必要な検査と原本記録
FSM23・24・25保留制御、判定と処置の記録権限を定めた承認、現物の隔離
FSM22関連記録の抽出事故対応、回収訓練、連絡網

追跡と事故対応の試験は、それぞれ少なくとも年1回実施して結果を保管する運用を整えてください。HACCP計画、危害分析、CCP監視、アレルゲン、衛生・清掃・防虫防鼠、教育等は本版の管理対象外です。責任者が公式の全項目と現場の運用を照合し、不足を補ってください。

担当者選択に本人認証はなく、データベース自体の直接編集を防ぐ改ざん耐性もありません。信頼できる管理されたPC・社内LANで試行してください。仕入れ金額を含むデータへの権限制御、営業先からの利用、監査承認の役割分離は別途実装が必要です。ルーターのポート公開はしないでください。

AI発注書読取り・SX4連携は未実装です。AIを追加する際も確認前は下書きとし、受入判定・出荷可否の判断を自動で代行させない設計とします。
